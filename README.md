# 教学反馈与教学助手 Demo

一个本地运行的教学工作台，覆盖教学名单维护、晚辅/专项反馈采集、学生档案、周报生成，以及基于已有教学数据的 LLM 教学助手。教学助手通过 `.env` 统一配置模型，并以流式响应呈现回答。

## 技术栈

Python 3.11、FastAPI、Jinja2、SQLAlchemy、SQLite、openpyxl、httpx、python-dotenv、pytest；前端使用原生 JavaScript 接收教学助手的流式响应。

## 安装与运行

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m app
```

启动后访问 http://127.0.0.1:8000。

`python -m app` 会自动创建 `data/` 目录、升级 `data/teaching_demo.db`，并写入 85 条反馈指标及教学参考字典后启动服务。参考字典包括零阶至九阶、6 个晚辅档位，以及入学测评的 2 个模块、16 个维度和 96 条评分锚点。

## 数据库位置

- 数据库文件：`data/teaching_demo.db`（SQLite，WAL 模式，外键已启用）。
- 指标字典：`db/seed_indicators.sql`（首次启动自动写入，之后采用「缺则插入」语义，不覆盖已有行）。
- 教学参考字典：`db/seed_reference_data.sql`（阶段、档位和入学测评评分标准，同样采用「缺则插入」语义）。

## Excel 导出

在「历史记录」页用筛选条件过滤后，点击「导出 Excel」即可下载包含 4 个工作表（学生、班级、晚辅反馈、专项反馈）的 `.xlsx` 文件；导出会沿用当前筛选条件（含日期、班级、学生、类型、状态）。

## 学生档案

「学生档案」页（`/profiles`）是对有效反馈的只读聚合：进入 `/profiles/{student_id}` 可查看单个学生档案，内容包括基础信息、评级趋势、高频进步/薄弱指标与近期反馈备注。作废反馈不计入；档案由系统从同一批标准化记录自动生成，老师无需重复填写。页面底部的来源反馈默认折叠，展开后可打开对应的原始反馈。

## 周报中心

「周报中心」页（`/reports`）按班级与周期列出每名在班学生的反馈数量与周报状态，可勾选「未生成且有反馈」的学生批量生成，默认周期为最近一个完整自然周。生成的周报先以「草稿」保存，详情页采用双栏布局：左侧「给家长的话」是一篇可直接审核、编辑、复制的自然沟通正文，右侧「审核参考」保留优势、待关注、建议、数据概况与折叠的来源反馈。老师可保存、快捷改写（润色／更简短／重新生成）或用自然语言指令修改，所有机器改写先并排预览、确认后才替换。定稿后正文只读、可一键复制。每份周报通过 `weekly_report_source` 固化来源反馈，保证可追溯。

## 教学助手

「教学助手」页（`/chat`）以已有反馈、学生档案和已定稿周报为只读上下文，不会修改业务数据。

- 新建对话时可选择学生或班级范围，并指定开始、结束日期；对话中也可更新日期范围。
- 支持总结近期进步、分析薄弱项、起草家长沟通文案，以及围绕所选范围自由提问。
- 回答以流式方式生成；生成中可停止，失败或停止后可重试。会话支持搜索、重命名和归档。
- 每条回答的可追溯来源默认折叠，展开「回答依据」后可打开对应的原始反馈或周报。

家长沟通回答提供专用操作：

- 「复制文案」只复制面向家长的「可复制文案」，不包含「给老师的依据」，并自动排除 `[S#]` 来源标记。
- 「编辑文案」只修改当前页面上的显示内容，不写入数据库；刷新页面后会恢复原回答。

对话归创建它的老师所有；管理员和校区负责人可以只读查看其他老师的对话，但不能续聊、修改或归档。

## 模型配置

复制 `.env.example` 为 `.env`，填写 OpenAI 兼容模型服务的 API 地址、密钥和模型名称：

```dotenv
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=replace-with-your-api-key
LLM_MODEL=deepseek-v4-flash
```

`.env` 已加入 Git 忽略列表，不会提交到代码仓库。上述统一配置同时供教学对话与 AI 周报使用；模型服务须兼容 OpenAI Chat Completions，教学对话使用流式响应。旧版 `REPORT_AI_*` 配置仍可兼容，但不建议继续使用。

## 企业微信智能机器人

Teaching Agent 支持通过企业微信智能机器人私聊进行只读教学问答。接入采用 WebSocket 长连接，不需要为消息回调准备公网域名。

1. 在企业微信的「安全与管理 → 管理工具 → 智能机器人」创建机器人。
2. 选择「API 模式创建」和「使用长连接」，保存 Bot ID 与 Secret。
3. 在 `.env` 中配置并重新启动应用：

```dotenv
WECOM_BOT_ENABLED=true
WECOM_BOT_ID=你的BotID
WECOM_BOT_SECRET=你的Secret
```

如需让回答附带可点击的「查看依据」链接，可额外配置教师设备能够访问的 Teaching Agent 地址：

```dotenv
TEACHING_APP_BASE_URL=https://teaching.example.com
```

老师首次使用时，在网页右上角进入「账号设置」，生成 6 位绑定码，并在 10 分钟内私聊机器人发送 `绑定 123456`。绑定完成后，可直接发送「分析张三最近的表现」或「总结三年级A班最近的共性问题」。未指定日期时默认读取最近 28 天。

老师可在智能机器人私聊中发送图片，并在同一条消息写明学生姓名或 ID；群聊、语音和普通文件不处理，也不会通过机器人修改反馈、档案和周报。运行状态可通过 `/health/wecom` 查看。同一个 Bot ID 只能由一个应用进程保持长连接，因此启用机器人时不要启动多个应用进程。

## 家长图片与微信客服沟通

老师智能机器人和家长微信客服是两套彼此独立的企业微信入口：老师通过企业微信智能机器人私聊上传图片，需在同一条消息中注明学生姓名或学生 ID；家长则以普通微信用户／企业微信外部联系人身份，通过「微信客服」入口与机器人和老师沟通。机器人回复以「【机器人回复】」标识，老师回复以「【老师：姓名】」标识。

启用家长微信客服时，在 `.env` 配置以下六项（企业 ID、应用 Secret、微信客服账号 ID、回调 Token、回调 EncodingAESKey，以及启用开关）：

```dotenv
WECOM_CUSTOMER_ENABLED=true
WECOM_CUSTOMER_CORP_ID=你的企业ID
WECOM_CUSTOMER_SECRET=微信客服应用Secret
WECOM_CUSTOMER_OPEN_KFID=微信客服账号ID
WECOM_CUSTOMER_CALLBACK_TOKEN=回调Token
WECOM_CUSTOMER_CALLBACK_AES_KEY=43位EncodingAESKey
```

在企业微信管理后台将回调地址设为 `https://你的域名/wecom/customer/callback`。本机或内网运行时，需要通过安全隧道或其他受控方式提供可访问的公网 HTTPS 回调；不要将未加密的本机服务直接暴露到公网。`/health/wecom-customer` 只返回启用状态、就绪状态和最近错误时间，不会包含凭证。

管理员先为学生生成一次性家长邀请码，再交给家长通过微信客服绑定；邀请码可由管理员在学生档案的家庭管理区域生成。家长不能使用老师账号的绑定码。每名学生在系统中有独立 ID，家长关系与老师负责关系均关联到该学生。

图片默认上限为 10 MB，老师上传后有 15 分钟待确认时间；可用 `STUDENT_MEDIA_ROOT`、`STUDENT_MEDIA_MAX_BYTES` 和 `PENDING_MEDIA_MINUTES` 调整图片目录、大小上限和待确认时长。运行系统时必须同时备份 `data/teaching_demo.db` 和 `data/student_media`，两者缺一会导致图片记录与文件不一致。

当前默认按单机、单进程部署。微信客服回调去重锁、短时邀请码提示缓存属于进程内状态，多 worker 部署可能造成跨进程重复处理或提示丢失，暂不支持多 worker。老师通知和家长回复采用持久化 outbox 的至少一次投递：进程若在外部渠道已接受消息、但数据库尚未记录成功时崩溃，重试可能造成重复消息。

## 周报生成与改写

周报中心页面只显示「生成周报」，不让老师选择规则模板或 AI。系统优先使用已配置的智能生成器；当模型未配置、调用失败或输出未通过校验时，自动回退到本地的自然语言模板生成器（完全离线、随时可用），并在周报中记录「生成说明」（`generation_note`，仅内部留存、不在页面展示）。周报生成永远不会因模型服务缺失或异常而被阻断。

改写（润色／更简短／重新生成／自然语言指令）复用同一套模型配置；改写只返回候选正文、不直接写数据库，确认后才替换，且不改动内部优势、待关注、建议和来源反馈。改写服务不可用时，老师仍可直接编辑正文。

## 测试

```powershell
pytest -q
```

测试覆盖登录与权限、反馈录入和导出、学生档案、周报，以及教学助手的会话、上下文、提示词与流式响应。家庭沟通测试覆盖老师图片归档、家长邀请码、家长授权查询、微信客服回调与消息、机器人/老师回复来源标注和端到端中转；端到端测试通过本地假企业微信客户端与回调加解密器运行，不连接真实企业微信。

## 安全备份

在应用停止运行后，同时复制 `data/teaching_demo.db` 和 `data/student_media` 才是完整备份；不要在应用运行期间拷贝（WAL 模式下可能有未合并的日志）。如果通过 `STUDENT_MEDIA_ROOT` 修改了图片目录，也要备份该目录。

## 登录与权限

启动后访问 http://127.0.0.1:8000 会跳转到登录页。

- **初始管理员**：`管理员` / `admin123`（首次启动自动创建，登录后请在「教师」页修改密码）。
- **权限分层**：角色为 `管理员` 或 `校区负责人` 的账号可访问全部数据与「基础信息」管理页；普通老师只能看到自己负责的班级、自己创建的场次，以及对应的反馈历史与导出结果。
- 密码使用 PBKDF2-SHA256 加盐哈希存储，会话通过服务端签名 Cookie 维持；历史教师若 `password_hash` 为空则不能登录。

## 说明

本项目是一个数据采集演示，权限控制面向本地试用场景；默认密码、默认会话密钥和当前密码策略不适合生产环境（如需上线，建议补充 HTTPS、更强的会话密钥与密码策略）。
