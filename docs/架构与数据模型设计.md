# 晚辅&专项课 量化反馈系统 · 架构与数据模型设计

> 把《晚辅&专项课_量化反馈表全套》从「三张独立 Excel」改造为一个「学生成长数据系统」的底层架构。
> 本阶段只交付 **Schema + 设计文档**（`db/schema.sql`、`db/seed_indicators.sql`、本文档），
> 不写 Web 应用代码；但 Schema 按未来 **Web 应用（Python + SQLite）** 方向设计，后续接 FastAPI 后端 + 前端表单无需返工。

---

## 1. 背景与目标

### 现状问题
- 老师每天在 Excel 里逐格填写，数据散落在各张表、各个月的副本里，无法沉淀。
- 无法自动形成**学生个人成长档案**、**班级学情视图**、**月度趋势**。
- 学生基础信息（年级、九阶阶段、晚辅档位）每天重复填写，易出错、难复用。

### 目标
1. 数据只填写一次，自动关联，不重复录入。
2. 学生档案、班级视图、月度汇总都从**同一条条标准化记录**自动生成。
3. 指标可配置（改措辞、增指标不动表结构）。
4. 换班/升班不丢历史。

### 核心原则
> **一人一档、一课一记录、一班一视图、一次填写、自动汇总**

## 2. 四层架构与数据流

```text
授课老师
   ↓ 选择班级 → 选择学生 → 选择课程类型
   ↓                        ├─ 晚辅课每日反馈
   ↓                        └─ 专项课单次反馈
Agent 辅助填写、检查、标准化
   ↓ 结构化写入数据库
┌──────────────┬──────────────┐
│ 班级学情数据库 │ 学生个人成长档案 │   ← 都是同一批记录的查询视图
└──────────────┴──────────────┘
   ↓
月度自动汇总
```

**关键设计点**：数据库里**不**按「一学生一表 / 一班级一文件」存。Excel 只是填写/展示形式，
底层把数据拆成一条条标准化记录；学生档案、班级档案都是 Agent 从数据库「调出来」的视图。

## 3. ER 关系图

```text
teacher ──head_teacher──▶ class
                              ▲
                              │ enrollment(学生—班级，可多条、可换班)
student ──────────────────────┘
   │  │  │
   │  │  └──▶ assessment ──▶ assessment_score(维度得分)
   │  ├──▶ daily_feedback ──▶ daily_feedback_indicator ──▶ indicator
   │  └──▶ special_feedback ─▶ special_feedback_indicator ─▶ indicator
   └──▶ monthly_summary

indicator：指标字典（85 条勾选项 + 分类）
stage_dict：九阶阶段字典
```

关系要点：
- `student : enrollment : class` = 多对多（一名学生可上多个班；一班级有多名学生）。
- `daily_feedback / special_feedback : indicator` = 多对多（一次反馈勾选多个指标；一个指标被多次引用）。
- `student : daily_feedback / special_feedback / monthly_summary / assessment` = 一对多。

## 7. 查询逻辑说明

### 7.1 学生个人档案
以 `student_id = ?` 为入口，拉取：
- 基础信息：`student` 单表。
- 晚辅记录：`daily_feedback`（按 date 升序）+ `daily_feedback_indicator` JOIN `indicator` 展开勾选项。
- 专项记录：`special_feedback` + `special_feedback_indicator` JOIN `indicator`。
- 入学测评：`assessment` + `assessment_score`。
- 月度汇总：`monthly_summary`（按 period）。
- 九阶成长轨迹：可由 `student.current_stage` + `assessment.stage_result` + 历史档案推得。

```sql
-- 某学生某次晚辅的完整勾选还原
SELECT i.category, i.text
FROM daily_feedback f
JOIN daily_feedback_indicator fi ON fi.feedback_id = f.feedback_id
JOIN indicator i ON i.indicator_id = fi.indicator_id
WHERE f.student_id = 'S001'
ORDER BY f.date, i.category, i.sort_order;
```

### 7.2 班级学情视图
以 `class_id = ?` 为入口，先经 `enrollment` 得到学生清单，再聚合各自最近一次 `daily_feedback` 的评级：

```sql
SELECT s.student_id, s.name,
       AVG(f.rating_knowledge) AS avg_k,
       AVG(f.rating_habit)     AS avg_h,
       AVG(f.rating_mindset)   AS avg_m
FROM enrollment e
JOIN student s ON s.student_id = e.student_id
LEFT JOIN daily_feedback f ON f.student_id = s.student_id AND f.class_id = e.class_id
WHERE e.class_id = 'C001' AND e.status = '在读'
GROUP BY s.student_id;
```

### 7.3 月度汇总（自动计算）
月初/月末评级 = 当月首条 / 末条 `daily_feedback` 的三维度评级，成长变化 = 末 − 首：

```sql
-- 取某学生某月的首末评级
SELECT student_id,
       substr(date,1,7) AS month,
       (SELECT rating_knowledge FROM daily_feedback
         WHERE student_id = f.student_id AND date LIKE '2026-09%'
         ORDER BY date ASC  LIMIT 1) AS k_start,
       (SELECT rating_knowledge FROM daily_feedback
         WHERE student_id = f.student_id AND date LIKE '2026-09%'
         ORDER BY date DESC LIMIT 1) AS k_end
FROM daily_feedback f
WHERE date LIKE '2026-09%'
GROUP BY student_id;
```

## 8. 未来 Web 应用落地建议（本阶段不实现）

- **后端**：Python + FastAPI + SQLite（本机 Python 3.11 已具备 `sqlite3`，零配置起步）。
- **前端**：React（与 Trading Agent 前端技术栈一致）或服务端渲染；表单按 `indicator` 字典动态渲染，勾选项不写死。
- **权限**：`teacher.role` 分层（教师看自己班 → 校区负责人看校区 → 管理员看全部）；细粒度「可管理班级」可加 `teacher_class` 映射表。
- **Agent 智能分析**（后续）：自动评语、趋势预警、升班建议，都建立在当前 Schema 之上，无需改表。

## 9. 待确认项（来自扫描件 PDF，正文无法直接提取）

1. **九阶阶段准确名称/含义**：已按「一阶~九阶」顺序 seed 进 `stage_dict`，具体每阶的学能定义以《九阶全周期学能成才体系（慧诺特）.pdf》为准，需人工校对（可 OCR）。

4. **年级范围**：是否含初中（当前按小学一年级~六年级假设）。
