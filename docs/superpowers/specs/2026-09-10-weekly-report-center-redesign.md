# 周报中心双层内容与审核工作台设计

日期：2026-09-10
状态：已确认

## 1. 背景

现有周报中心把周报建模为 `summary`、`strengths`、`concerns` 和 `suggestions` 四个结构化字段。草稿详情页直接要求老师编辑 JSON 数组，规则生成器则把反馈数量、评分变化和指标名称拼接为固定句式。

这套设计保证了离线可用、事实可追溯和人工定稿，但它更像结构化记录管理后台，不像帮助老师完成家长沟通的写作工具。老师必须理解内部数据格式，生成内容也缺少自然叙事、具体观察和可执行建议。

本次改造将周报重新定义为“两层内容”产品：家长看到的是自然、完整、可直接发送的沟通正文；老师仍能在同一页面查看结构化分析和原始反馈依据。

## 2. 目标

1. 让老师生成后首先得到一篇可直接审核、修改和复制的家长沟通正文。
2. 保留优势、待关注、建议、评分变化和来源反馈等内部审核信息。
3. 隐藏 JSON、模型类型和回退方式等技术细节。
4. 支持直接编辑、快捷改写和自然语言指令修改，所有机器改写均先预览再替换。
5. 保持现有权限、来源追溯、离线回退和定稿不可变规则。
6. 兼容已有草稿和定稿周报，不使用 AI 重写历史内容。

## 3. 非目标

- 不自动发送微信、短信或邮件。
- 不建设机构品牌模板库。
- 不引入家长画像、家庭画像或心理分析。
- 不实现完整版本历史或任意版本恢复。
- 不实现多人协同审核。
- 不新增后台模型配置页面。
- 不改变原始反馈的事实源地位，也不允许周报反向修改反馈。

## 4. 已确认的产品决策

- 采用双层内容模型：家长沟通正文为主，结构化分析与来源为内部审核层。
- 详情页采用精简双栏布局：左侧正文，右侧审核参考。
- 首页采用紧凑筛选列表，不采用流程看板或学生卡片。
- 默认周期为最近一个完整自然周，即上一个周一至周日；允许自定义周期。
- 页面只显示“生成周报”，不让老师选择规则模板或 AI。
- 支持快捷改写和对话式修改。
- 对话修改后并排显示原稿与修改稿，确认后才替换。
- 不保存完整改写版本历史。

## 5. 信息架构与流程

```text
选择班级和周期
  → 查看班级学生、反馈数量与周报状态
  → 单个或批量生成
  → 系统生成家长正文和内部分析
  → 老师在双栏详情页审核
  → 直接编辑 / 快捷改写 / 对话修改
  → 对比原稿与候选稿
  → 确认替换
  → 保存并定稿
  → 复制正文或查看原始依据
```

周报生命周期仍为：

```text
未生成 → 草稿 → 已定稿
```

`生成中` 和 `修改稿预览` 是界面临时状态，不写入周报生命周期字段。

## 6. 周报中心首页

### 6.1 页面结构

页面顶部包含：

- 标题“周报中心”；
- 简短说明；
- 主操作“批量生成”；
- 班级筛选；
- 周期筛选，默认最近一个完整自然周；
- “自定义周期”次级入口；
- 状态筛选：全部、未生成、待审核、已定稿、暂无数据。

主区域使用紧凑列表，每行对应所选班级和周期内的一名有效在班学生，而不只是已经生成的周报。列包括：

| 列 | 内容 |
|---|---|
| 学生 | 学生姓名 |
| 周期 | 当前筛选周期 |
| 有效反馈 | 数量；为零时显示“暂无数据” |
| 周报摘要 | 草稿或定稿正文的首段摘要；未生成时为空 |
| 状态 | 未生成、待审核、已定稿或暂无数据 |
| 更新时间 | 最近保存或定稿时间 |
| 操作 | 生成、继续审核、查看/复制 |

### 6.2 行状态规则

- 有反馈且无周报：显示“未生成”和“生成”。
- 无反馈且无周报：显示“暂无数据”，生成按钮不可用，并说明“周期内没有有效反馈”。
- 存在草稿且无定稿：显示最新草稿为“待审核”，操作为“继续审核”。
- 存在定稿：优先显示定稿状态，操作为“查看/复制”。同周期的其他草稿不覆盖定稿状态。
- 同一学生、班级和周期仍允许存在多份草稿；首页只展示最新草稿，其他草稿通过详情页的“同周期草稿”次级入口查看。

### 6.3 批量生成

- 老师勾选一个或多个“未生成且有反馈”的学生后，显示批量操作栏。
- 主按钮统一为“生成周报”，不显示“规则模板”和“AI 生成”。
- 每个学生独立生成；单个失败不回滚其他学生。
- 生成过程中禁用重复提交，并逐项显示生成状态。
- 完成后，成功项进入“待审核”，失败项就地显示具体原因。

## 7. 周报详情页

### 7.1 顶部信息

页面顶部以阅读友好的形式展示：

- 学生姓名和“成长周报”标题；
- 班级；
- 周期；
- 草稿或已定稿状态；
- 最近更新时间。

不再使用五行元数据表，也不展示生成方式。草稿页顶部只保留“保存”和“定稿”两个主要操作。

### 7.2 左侧：家长沟通正文

左侧是页面的视觉和操作主区域，字段标题为“给家长的话”。正文使用普通多行编辑器，不出现 JSON 或内部字段名。

草稿状态支持：

- 直接修改正文；
- 保存；
- 润色全文；
- 更简短；
- 重新生成；
- 输入自然语言修改指令。

已定稿状态：

- 正文只读；
- 支持一键复制；
- 不显示改写和保存操作。

### 7.3 右侧：审核参考

右侧使用一个轻量容器，不堆叠多个高对比卡片。依次展示：

- 优势；
- 待关注；
- 建议；
- 数据概况，包括有效反馈数量和最重要的评分变化；
- 折叠的原始反馈列表。

右侧信息只辅助审核，不直接进入复制正文。每条来源仍链接到对应晚辅或专项反馈详情。

### 7.4 响应式与视觉规范

- 桌面端正文与审核参考约为 `1.9 : 0.8`。
- 窄屏时右栏移动到正文下方，不产生横向滚动。
- 页面标题约 24px，正文不小于 16px，辅助文字不小于 13px。
- 正文行高为 1.7–1.85，控制每行阅读长度。
- 操作按钮点击区域至少 44px。
- 使用现有暖色视觉语言，但减少边框、阴影、色块和状态标签数量。
- 颜色不是状态的唯一表达方式；所有输入均有可见标签和键盘焦点。

## 8. 双层内容模型

`weekly_report` 新增：

| 字段 | 类型 | 含义 |
|---|---|---|
| parent_message | TEXT | 完整家长沟通正文，草稿可编辑，定稿后只读 |

保留现有字段：

- `summary`：内部整体判断；
- `strengths`：内部优势列表；
- `concerns`：内部待关注列表；
- `suggestions`：内部建议列表；
- `generation_mode`：实际生成方式，仅内部记录；
- `generation_note`：回退或异常说明，仅内部记录。

首期不新增改写版本表。候选稿只存在于改写预览响应中，老师确认后才写入 `parent_message`。

## 9. 上下文、生成与校验

### 9.1 周报上下文

继续由独立上下文构建器读取并聚合：

- 学生和班级名称；
- 周期；
- 有效反馈数量；
- 评分变化；
- 高频优势和薄弱指标；
- 最近老师备注；
- 来源反馈编号。

上下文构建器不生成自然语言，不修改业务数据。

### 9.2 首次生成输出

生成器统一输出：

```json
{
  "parent_message": "完整家长沟通正文",
  "summary": "内部整体判断",
  "strengths": ["优势"],
  "concerns": ["待关注"],
  "suggestions": ["建议"]
}
```

页面不暴露生成器类型。系统优先使用已配置的智能生成器；模型未配置、调用失败或输出校验失败时，自动调用新版自然语言模板生成器。

### 9.3 自然语言模板回退

回退模板生成完整正文，而不是把 JSON 列表直接交给老师。正文按以下顺序组织：

1. 简短问候和本阶段总体观察；
2. 一至两个有事实依据的积极表现；
3. 一个最需要关注的问题；
4. 一个具体、低负担、可执行的家庭配合建议；
5. 教师后续关注说明。

只有一次有效反馈时，文案使用“本阶段的一次反馈中观察到”等限定表达，不得声称形成趋势。没有相应数据时省略该结论，不补造内容。

### 9.4 内容校验

首次生成、快捷改写、对话改写和候选稿确认时均执行统一校验：

- 家长正文非空，长度在产品限制内；
- 结构化字段类型和数量正确；
- 明确数字能从上下文得到支持；
- 不包含未经记录的成绩、家庭情况或心理诊断；
- 不使用人格定性标签；
- 不把老师备注或原始反馈中的文本当作系统指令；
- 对话改写不得改变学生、班级、周期和事实依据。

## 10. 快捷与对话式修改

快捷操作“润色全文”“更简短”“重新生成”和自由输入指令共用同一个改写服务。

输入包括：

- 当前 `parent_message`；
- 老师的快捷动作或自然语言指令；
- 当前周报的结构化上下文；
- 固定的安全与事实约束。

输出只包含候选 `parent_message`，不修改内部优势、待关注、建议和来源反馈。

服务端返回预览页，桌面端并排展示“原稿 / 修改稿”，窄屏端上下排列。老师可以：

- 确认替换；
- 取消并返回原稿；
- 修改指令后再次生成。

确认替换时再次校验候选稿，并确认周报仍处于草稿状态。若预览期间原稿已被其他保存操作更新，则拒绝覆盖并提示重新生成预览。

## 11. 服务边界

模块职责保持分离：

- `context`：读取并聚合事实快照；
- `generators`：首次生成家长正文和内部分析；
- `rewriter`：根据动作或指令生成候选正文；
- `validation`：校验首次输出和改写输出；
- `service`：保存草稿、确认替换、定稿和批量隔离；
- `routes/templates`：筛选列表、双栏审核和预览交互。

模型配置继续沿用现有统一配置。模型异常不得阻断规则生成、直接编辑、保存、定稿和复制。

## 12. 异常处理

- 首次智能生成失败：自动使用自然语言模板，生成成功后不在主界面显示技术错误。
- 对话或快捷改写失败：保留原稿，提示可以直接编辑或重试。
- 保存失败：重新渲染老师已输入的正文，不清空编辑内容。
- 批量部分失败：成功项提交，失败项单独报告。
- 无有效反馈：禁止生成并说明原因。
- 已定稿报告：保存、改写、替换请求返回冲突，不改变内容。
- 同周期已有定稿：其他草稿不能再次定稿。

## 13. 旧数据迁移

数据库升级时为 `weekly_report` 增加 `parent_message`。已有记录使用确定性格式组合正文：

```text
总结

优势：……

待关注：……

建议：……
```

迁移不调用模型，也不产生新事实。

- 旧定稿：保持只读，组合后的正文用于展示和复制。
- 旧草稿：组合后可继续直接编辑，也可由老师主动重新生成。
- 原有结构化字段、实际生成方式、生成说明和来源关联全部保留。

## 14. 权限与安全

- 管理员继续访问全部班级。
- 普通老师只能查看和操作自己负责班级的学生与周报。
- 首页学生状态投影、详情、生成、保存、改写、替换和定稿均执行服务端班级范围校验。
- 模型只接收完成当前周报所需的最小上下文，不接收家庭信息。
- 原始反馈和老师备注作为不可信数据，仅用于事实材料，不得覆盖系统指令。
- 定稿后正文和结构化分析均不可编辑。

## 15. 测试与验收

### 15.1 服务与模型测试

- 上一个完整自然周计算正确，跨月和跨年边界正确。
- 首页按班级、周期和状态形成每名学生的正确行状态。
- 多份草稿和单一定稿的显示优先级正确。
- 首次智能生成成功、未配置、异常和非法输出路径正确。
- 自然语言模板只使用已有事实。
- 单条反馈不生成趋势性表述。
- 对话改写只返回候选正文，不直接写数据库。
- 候选稿确认前原稿不变，确认后才替换。
- 过期预览不能覆盖更新后的草稿。
- 已定稿周报不能保存或改写。

### 15.2 页面与权限测试

- 页面不出现“JSON 数组”等技术术语。
- 首页筛选、批量勾选、禁用状态和部分失败提示正确。
- 草稿详情默认显示家长正文和审核参考。
- 定稿详情支持复制正文和查看来源。
- 普通老师不能查看或修改非负责班级周报。
- 375px、768px、1024px 和 1440px 宽度下无横向滚动。
- 表单标签、键盘焦点、文字对比度和点击区域符合可访问性要求。

### 15.3 回归测试

完整测试套件必须确认以下既有功能不受影响：

- 登录与权限；
- 晚辅和专项反馈录入；
- 历史记录；
- 学生档案；
- 教学助手；
- Excel 导出；
- 已有周报来源追溯与单一定稿约束。

## 16. 完成标准

- 老师无需理解 JSON 或模型配置即可生成周报。
- 详情页首先呈现一篇自然、完整、可编辑的家长沟通正文。
- 内部结构化分析和原始依据仍可快速审核和追溯。
- 快捷与对话式修改均先预览，未经确认不覆盖原稿。
- 智能服务不可用时仍能生成可读正文并完成保存、定稿和复制。
- 旧周报完整兼容且不被 AI 重写。
- 新增测试和完整回归测试全部通过。
