# 家长沟通文案复制与本地编辑设计

## 目标

为教学助手生成的家长沟通回复增加“复制文案”和“编辑文案”能力。操作范围仅限回答中“可复制文案”与“给老师的依据”之间的正文，避免把内部依据或 `[S#]` 引用发送给家长。

## 范围

- 历史回答和新生成的流式回答均支持。
- 只有同时识别到“可复制文案”区段及有效正文时才显示操作按钮。
- 编辑仅修改当前页面中的显示内容，不请求后端、不写入数据库、不改变原始聊天记录。
- 普通问答、薄弱分析、进步总结及“给老师的依据”保持原样。
- 回答依据继续默认折叠。

## 交互设计

在可复制文案区段附近显示两个轻量按钮：

- “复制文案”：复制区段正文，不包含“可复制文案”标题、“给老师的依据”、引用标记及其他回答内容。复制成功后短暂显示“已复制”；剪贴板 API 不可用时提供手动复制回退。
- “编辑文案”：原地切换为预填当前文案的文本框，并显示“完成编辑”和“取消”。完成编辑后更新当前页面内容；取消则恢复进入编辑前的内容。

编辑完成后再次复制时，复制修改后的区段正文。空白内容不能完成编辑，避免产生不可复制的空文案。

## 实现方案

采用纯前端区段识别，不修改数据库、路由、SSE 事件或模型调用。

前端从每条成功的助手回答中提取完整文本，识别“可复制文案”标题和后续“给老师的依据”标题，将两者之间的正文作为操作目标。识别兼容普通标题、Markdown 标题、加粗标题以及中英文冒号。无法可靠识别区段时不显示按钮。

历史消息在页面初始化时扫描；流式回答在 `done` 事件完成后扫描。按钮状态和本地编辑状态只附着于当前消息 DOM，不跨刷新保存。

## 错误与边界处理

- 缺少区段标题、正文为空或边界顺序异常时不显示操作按钮。
- 剪贴板写入失败时弹出包含文案正文的手动复制框。
- 编辑取消不改变原内容；完成编辑仅替换目标区段。
- 重试生成的回答在成功完成后重新识别，不继承失败回答的编辑状态。
- 只读或已归档对话仍允许本地复制和编辑，因为不会改变系统数据。

## 测试

- 验证普通、Markdown、加粗及带冒号的区段标题均能提取正确正文。
- 验证缺失边界、空正文和普通回答不显示操作按钮。
- 验证复制目标不含标题、回答依据和 `[S#]`。
- 验证编辑、取消、完成编辑及编辑后复制的行为。
- 验证历史回答初始化和流式回答完成后都会安装操作按钮。
- 运行完整项目测试，确认现有聊天、周报、档案和反馈流程不受影响。
