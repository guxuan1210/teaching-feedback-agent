# 教学助手聊天界面「温暖编辑感」设计

## 目标

在不改变聊天、引用、重试和跨端同步行为的前提下，重构教学助手页面的视觉层级与消息布局，解决当前消息横向拉满、渠道标签挤占正文、用户与助手缺少方向区分、长回答阅读困难的问题。

## 视觉方向

- 延续现有暖纸底、墨色和朱砂红品牌，不引入新的在线字体或图标依赖。
- 页面呈现克制、温和、专业的编辑感，避免高饱和 SaaS 蓝和装饰性效果。
- 正文字号保持约 14–15px、行高 1.65–1.75；长回答的有效行宽限制在约 65–75 个中文字符。
- 边框轻、阴影弱、圆角适中；焦点环和文字对比达到可访问性要求。

## 页面布局

- 桌面端维持左侧会话栏与右侧聊天区，侧栏固定约 240px，整体间距收紧。
- 聊天头部单独成层：第一行是对话标题和操作，第二行集中显示范围、班级与日期，不让元数据混入消息区。
- 消息流占据可用高度，内部阅读列最大宽度约 760px并水平居中，避免大屏文字横贯页面。
- 输入区固定在聊天区底部，快捷提问置于输入框上方；保持现有 Enter、Shift+Enter、停止生成和字数统计行为。
- 800px 以下侧栏继续使用抽屉；消息阅读列取消固定宽度，气泡最大宽度提高到约 86%，保证 375px 宽度无横向滚动。

## 消息组件

- 用户消息右对齐，助手消息左对齐，头像缩小到约 28px。
- 渠道标签与时间归入消息元信息行，不再作为头像与正文之间的独立 flex 子项。
- 用户气泡使用浅朱砂背景与右上小圆角；助手气泡使用暖白背景与左上小圆角，二者均限制最大宽度。
- 助手回答保留段落结构，引用入口置于气泡下方，显示为低强调文本链接；展开后的来源列表沿用现有数据和链接。
- 失败、生成中、重试、复制与本地编辑操作保留现有功能，只统一间距、按钮尺寸和状态色。
- 新产生的消息必须与服务端渲染历史消息使用同一 DOM 结构，确保网页/企业微信标签在流式生成后样式一致。

## 交互与范围

- 新建对话、搜索、日期更新、重命名、归档、回答依据、快捷提问和消息操作均保持原接口与行为。
- 本次只调整教学助手模板、聊天前端构建结构和聊天相关 CSS，不重做全站导航，不改变数据库或后端 API。
- 动效限定在 150–200ms 的颜色、边框和透明度过渡，并遵循 `prefers-reduced-motion`。
- 所有按钮保持至少 44px 的移动端点击区域和清晰键盘焦点。

## 验收标准

- 在 1440px 和更宽屏幕上，消息正文不会横向铺满聊天区，长回答可自然换行阅读。
- “网页／企业微信”标签位于消息元信息行，不再把气泡推向右侧或形成高而窄的标签列。
- 用户消息右对齐、助手消息左对齐；头像、气泡、标签和来源入口层级清晰。
- 375px、768px、1024px、1440px 下无横向滚动，侧栏和输入区行为正常。
- 历史消息、实时流式消息、失败消息、重试消息及来源展开样式一致。
- 现有聊天路由、SSE、快捷提问、复制编辑、跨端渠道标签和完整自动化测试保持通过。
