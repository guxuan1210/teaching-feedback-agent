# 登录权限与参考字典一致性收尾设计

日期：2026-09-06  
状态：待用户确认

## 1. 目标

收尾当前工作区已经实现的登录权限与教学参考字典扩展，确保 SQLAlchemy 模型、数据库升级逻辑、参考 `schema.sql`、README 和架构文档描述同一套实际能力。

## 2. 范围

本轮包含：

- 在参考 Schema 的 `teacher` 表中补齐可空的 `password_hash` 字段。
- 用自动化测试验证全新数据库和版本 1 数据库升级后均具备 `teacher.password_hash` 与 `student.late_care_level`。
- 保持数据库版本为 2，并验证升级过程保留已有教师、学生及自定义阶段数据。
- 更新架构文档中的模型、权限和当前实现状态，使其不再把尚未实现的测评记录、月度汇总表描述成现有表。
- 更新旧版 Demo 规格的状态说明，明确登录与权限已经作为后续扩展实现，避免与 README 冲突。

本轮不包含：

- 入学测评录入页面或 `assessment`、`assessment_score` 业务表。
- 月度汇总、趋势分析或 `monthly_summary` 表。
- 新角色、新页面、新的授权关系或生产级安全能力。
- 修改现有反馈录入、历史查询和 Excel 导出流程。

## 3. 一致性基准

可执行 SQLAlchemy 模型是当前应用行为的基准；`db/schema.sql` 必须能够独立创建与模型一致的 15 张表。增量升级由 `app/core/database.py` 负责：版本 1 升级到版本 2 时只增加缺失列，不覆盖已有业务数据或字典自定义内容。

登录字段保持可空，以兼容没有账号的历史教师记录。首次启动创建默认管理员，现有管理员不被覆盖。参考字典继续使用“缺则插入”语义。

## 4. 测试设计

- 扩展 Schema 镜像测试，断言 `teacher.password_hash` 存在。
- 扩展版本 1 升级测试，同时创建教师和学生旧数据；升级后断言两个新增列存在且原数据保持不变。
- 保留字典数量、排序、评分锚点完整性与幂等测试。
- 最后运行完整测试套件，并使用 `db/schema.sql` 创建临时数据库执行完整性和外键检查。

## 5. 完成标准

- 模型、升级代码和 `db/schema.sql` 的字段一致。
- README、架构文档与旧规格能清楚区分“已实现能力”和“未来能力”。
- 全部自动化测试通过。
- 从参考 Schema 新建的数据库通过 `PRAGMA integrity_check` 和 `PRAGMA foreign_key_check`。
